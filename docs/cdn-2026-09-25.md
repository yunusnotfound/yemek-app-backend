## Cloudflare önbellek kuralları

Kurulum sırasında panelde iki aktif Cache Rule doğrulandı:

1. **Public upload images - respect origin cache:** API hostname'indeki
   `/uploads/` için GET/HEAD istekleri; origin Cache-Control başlığına uyulur,
   başlık yoksa önbelleğe alınmaz. Tarayıcı TTL'i de origin başlığını izler.
2. **Bypass dynamic API and account responses:** `/api/`, `/api`, `/panel`,
   `/admin` ve `/auth` kapsamındaki dinamik yanıtlar için önbellek bypass edilir.

API verileri, oturum ve hesap yanıtları için ortak CDN önbelleği açılmadı.
Bu çalışma için ücretli Cloudflare özelliği etkinleştirilmedi.

**Smart Tiered Cache** açıldı; panelde origin için primary **FRA**, secondary
**ZRH** görüldü. Smart Topology Free planda kullanılabilir. Seçilen merkezler
Cloudflare tarafından zamanla güncellenebilir.

## Canlı origin proxy değişikliği

VPS bağlantısı `deploy@72.60.34.192`; Caddy container'ı `proxy-caddy-1`, sürümü
**v2.11.4**. Host dosyası `/srv/proxy/Caddyfile`, container içinde
`/etc/caddy/Caddyfile` konumuna salt okunur bind mount olarak bağlı.

Global `servers` bölümüne Cloudflare'ın yayımladığı **15 IPv4 + 7 IPv6 = 22
CIDR** eklendi. Liste kurulum anında resmi `ips-v4` ve `ips-v6` yanıtlarıyla
birebir karşılaştırıldı; özel ağlar veya bütün internet güvenilir sayılmadı.

```caddyfile
servers {
    trusted_proxies static 173.245.48.0/20 103.21.244.0/22 103.22.200.0/22 103.31.4.0/22 141.101.64.0/18 108.162.192.0/18 190.93.240.0/20 188.114.96.0/20 197.234.240.0/22 198.41.128.0/17 162.158.0.0/15 104.16.0.0/13 104.24.0.0/14 172.64.0.0/13 131.0.72.0/22 2400:cb00::/32 2606:4700::/32 2803:f800::/32 2405:b500::/32 2405:8100::/32 2a06:98c0::/29 2c0f:f248::/32
    trusted_proxies_strict
    client_ip_headers CF-Connecting-IP X-Forwarded-For
}
```

Yalnız Bitirgitsin API/web upstream'lerinde doğrulanmış tek kullanıcı IP'si
iletilecek şekilde `header_up X-Forwarded-For {client_ip}` eklendi:

```caddyfile
api.bitirgitsin.com {
    reverse_proxy bitir-yemek-app:3000 {
        header_up X-Forwarded-For {client_ip}
    }
    # Mevcut body limit, TLS ve güvenlik başlıkları korundu.
}

bitirgitsin.com, www.bitirgitsin.com {
    reverse_proxy bitir-yemek-web:3000 {
        header_up X-Forwarded-For {client_ip}
    }
    # Mevcut body limit, TLS ve güvenlik başlıkları korundu.
}
```

Bu, Express'in mevcut özel ağ proxy güveni ile birlikte gerçek istemcinin
rate-limit anahtarına ulaşmasını sağlar. Güvenilmeyen bir kaynaktan doğrudan
origin'e gelen isteğin sahte CF/XFF başlıkları kabul edilmez. Paylaşılan
Caddyfile'daki IELTS ve Hırdavat Gezgini site blokları değiştirilmedi.

Repo şablonu da [proxy/Caddyfile](../proxy/Caddyfile) içinde güncellendi.
Şablondaki örnek email/API domain'i canlı dosyanın yerine doğrudan
kopyalanmamalıdır; canlı dosyada gerçek alan adları ve diğer siteler bulunur.

### Caddy yedeği ve kontroller

- Yedek: `/srv/proxy/Caddyfile.before-cloudflare-20260925T131612Z`
- Dağıtılan dosyanın SHA-256 değeri:
  `6e7594a2294aa54aa58c7d99e27189a90a31c02c82e102b0838a8b083fc5803c`
- Önce aday dosya aynı Caddy sürümünde `adapt --validate` ile doğrulandı.
- Dosya bind mount'unun inode'u korunarak güncellendi; canlı `validate` ve
  kesintisiz `reload` başarılı oldu.
- Aynı container image'ıyla, dış ağa kapalı geçici fixture'da dört kontrol
  geçti: güvenilmeyen CF/XFF başlıklarının yok sayılması, güvenilir CF
  başlığının upstream XFF'e aktarılması, strict XFF fallback'in sahte sol
  adresi atlaması ve IPv6 istemci adresinin korunması. Fixture kaldırıldı.
- Canlı origin'de normal istek ve iki ayrı sahte CF/XFF isteği aynı API
  limitini `98 → 97 → 96` azalttı.
- DNS aktivasyonundan sonra aynı istemcinin doğrudan origin ve Cloudflare
  istekleri aynı limiti `91 → 90` azalttı; Cloudflare IP'si ayrı bir kullanıcı
  olarak görülmedi.
- Origin üzerinden API sağlık kontrolü, apex/www web, `ieltsco.com` ve
  `www.hirdavatgezgini.com` HTTPS `200` döndürdü. API DB ve Redis bağlantıları
  sağlıklıydı.

Gerekirse host üzerinde Caddy geri dönüşü:

```sh
cp -p /srv/proxy/Caddyfile.before-cloudflare-20260925T131612Z /srv/proxy/Caddyfile
docker exec proxy-caddy-1 caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker exec proxy-caddy-1 caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
```

Geri dönüş eski dosyaya yapılacaksa o tarihten sonraki diğer site değişiklikleri
önce karşılaştırılmalıdır. Bind mount nedeniyle dosyayı `mv` ile değiştirmek
yerine mevcut dosyanın içeriği güncellenmelidir.

## Mobil kaynak kodu incelemesi

`AppCachedImage` değişikliği için bağımsız read-only incelemede engelleyici
regresyon bulunmadı: süre dolduğunda indirme aboneliği korunuyor, URL değişince
zamanlayıcı yeniden başlıyor ve resim çözme boyutu üst widget ölçülerinden
hesaplanıyor. İncelenen çağıranlar sabit veya sınırlandırılmış alan sağlıyor.
Backend testleri public görsel TTL/CORS ayrımını, hata durumlarını ve API
limitlerinin korunmasını kapsıyor.

Mobilde 15 büyük PNG kayıpsız WebP olarak paketlenecek şekilde güncellendi.
Her RGBA pikseli Git'teki orijinaliyle karşılaştırıldı: yerel varlıklar
**34,94 MB → 24,78 MB**, toplam **10,16 MB (%29,1)** azaldı. Silinen yerel
PNG yollarına kalan referanslar tarandı; mevcut canlı katalog PNG URL'leri
korundu. ZIP benzeri sıkıştırmada ölçülen varlık farkı yaklaşık 9,95 MB.

`imageCdnUrl` yalnız public, query/credential içermeyen production upload
URL'lerini **320/640/960/1280 px** genişlik seçeneklerine dönüştürüyor.
Kartlar ve harita logoları aynı yardımcıyı kullanıyor; WebP kalite 85,
`fit=scale-down` ve `onerror=redirect` uygulanıyor. Yerel, üçüncü taraf,
signed veya zaten dönüştürülmüş URL'ler değiştirilmez. Widget gereksiz tam
boyutlu çözme/PNG yeniden kodlama işini kaldırıyor ve indirmesi geç tamamlanan
görsellerin gösterilmesine izin veriyor.

İlk mobil değişikliklerde 30 hedefli test, CDN entegrasyonu sonrası 21
hedefli test geçti; Flutter analyze temiz. Test kümeleri örtüşür ve bu
sayılar toplanmış benzersiz test sayısı olarak sunulmamalıdır.

**Mobil sürüm yayımlanmadı.** Bu değişiklikler kaynak kodunda hazırdır;
